# game-design-knowledge

Agent Skill для геймдизайна в любом жанре: концепт и опоры, прототипы, документация для людей и ИИ-агентов, системный дизайн и баланс, экономика, плейтесты и метрики, автоматическая симуляция баланса ботами, ревью дизайна и архитектура кода игры.

Скилл даёт ИИ-агенту (Claude Code, claude.ai и другим инструментам с поддержкой формата [Agent Skills](https://agentskills.io)) четыре вещи:

- **библиотеку знаний** — сотни ссылок на книги, статьи, доклады GDC, исследования и разборы игр, разложенных по категориям. У каждой ссылки есть автор, год и пояснение, зачем её читать. Главная таблица — «симптом → решение → источник» почти на сто типичных проблем дизайна: преимущество первого хода, снежный ком, мана-скрю, analysis paralysis, гринд, инфляция и другие;
- **шаблоны документов** — one-sheet с опорами, спецификация фичи для программиста и ИИ-агента, бриф прототипа, план плейтеста, журнал дизайна, целевые коридоры метрик;
- **скрипты замеров** — сводка логов симуляций и плейтестов в метрики с доверительными интервалами, сравнение с базовой линией по целевым коридорам, расчёт числа партий;
- **пайплайн** — опрос, концепт и целевые метрики, прототип, спецификация, тесты правил, измерительный стенд, базовый замер, ревью кода и дизайна, поиск решений в библиотеке, изменения и повторный замер. Правка принимается, только если целевая метрика приблизилась к коридору, а остальные не ухудшились.

Состояние знаний — октябрь 2026. Тексты справочников на русском, названия источников — в оригинале.

## Состав

```text
game-design-knowledge/
├── SKILL.md                     точка входа: куда смотреть и как работать
├── references/
│   ├── pipeline.md              пайплайн геймдизайна с циклом замеров
│   ├── mechanics-patterns.md    паттерны механики и таблица «симптом → решение → источник»
│   ├── foundations.md           фреймворки: MDA, линзы, петли, мотивация, game feel
│   ├── systems-balance.md       баланс, вероятности, петли обратной связи, экономика, ориентиры
│   ├── playtesting-metrics.md   плейтесты, метрики, симуляции ботами, статистика
│   ├── design-review.md         ревью дизайна: эвристики, обучение, доступность
│   ├── documentation.md         one-sheet, GDD, спецификации для агентов, прототипы, продакшн
│   ├── architecture-code.md     движок правил, data-driven, детерминизм, игровой ИИ, тесты
│   ├── genres.md                карточные игры, рогалики, уровни, нарратив, файтинги, MMO, VR и другие
│   └── books.md                 книги, курсы, каналы и маршрут чтения
├── assets/                      шаблоны документов и пример targets.json
└── scripts/
    ├── design_metrics.py        JSONL партий → метрики
    ├── metrics_compare.py       базовая линия против повторного замера и коридоров
    └── sample_size.py           сколько партий или игроков нужно
```

Агент загружает `SKILL.md`, когда задача касается геймдизайна. Справочники он открывает только тогда, когда нужен конкретный раздел, поэтому скилл почти не занимает контекст, пока не используется.

## Установка

**Claude Code: для всех проектов**

```bash
git clone https://github.com/Betreazen/game-design-knowledge-skill.git
cp -r game-design-knowledge-skill/game-design-knowledge ~/.claude/skills/
```

**Claude Code: для одного проекта.** Скопируйте папку `game-design-knowledge` в `.claude/skills/` в корне проекта и закоммитьте её.

**claude.ai.** Заархивируйте папку `game-design-knowledge` в zip и загрузите в разделе Skills настроек claude.ai. Во frontmatter только стандартные поля `name` и `description`.

**Другие агенты (Codex, Gemini CLI, GitHub Copilot, Cursor).** Скопируйте папку в `.agents/skills/` проекта.

Скриптам нужен Python 3.10+ без сторонних пакетов.

## Использование

Скилл срабатывает сам, когда задача касается геймдизайна. В Claude Code его можно вызвать и явно командой `/game-design-knowledge`.

Примеры запросов:

- «Составь one-sheet и опоры для карточной игры по моей идее и предложи целевые коридоры метрик»
- «Первый игрок побеждает в 57% партий. Что можно сделать?»
- «Напиши спецификацию механики "атака лидера" для агента-программиста с примерами правил»
- «Сделай стенд: безголовый симулятор, жадный бот и бот на ISMCTS, лог в JSONL»
- «Сравни метрики до и после патча и скажи, принимать ли правку»
- «Проведи ревью дизайна обучения по эвристикам и чеклисту доступности»
- «Что почитать системному дизайнеру?»

Свой симулятор пишет одну строку JSONL на игрока в партии, а скрипты считают метрики:

```bash
python3 game-design-knowledge/scripts/design_metrics.py runs.jsonl --rate win --num turns \
  --by went_first --by deck --out metrics/before.json
python3 game-design-knowledge/scripts/metrics_compare.py metrics/before.json metrics/after.json \
  --targets design/targets.json
```

## Пометки в справочниках

- `[устарело]` — у материала есть замена, и она указана рядом.
- `[не проверено]` — ссылку или факт не удалось подтвердить по первоисточнику; его стоит перепроверить.

Числовые ориентиры — отправная точка для своих коридоров, а не отраслевой стандарт.
