# UX и UI игр

Справочник по интерфейсу для игр любого жанра: основы game UX, типы HUD, читаемость, меню и потоки экранов, UI по жанрам и замеры интерфейса. В [пайплайне](pipeline.md) он нужен на этапе 9 (ревью интерфейса) и на этапе 10, когда симптом связан с экраном, вводом или пониманием состояния игры. Эвристики юзабилити, обучение и доступность подробно разобраны в [design-review.md](design-review.md), game feel — в [foundations.md](foundations.md#14-game-feel-и-сок-swink-jonasson--purho-nijman). Здесь на них только ссылки.

Реализация интерфейса в конкретном движке (узлы, контейнеры, темы, фокус) сюда не входит: она описана в скиллах по движкам, например в gdscript-knowledge для Godot.

Пометки: `[не проверено]` — факт из одного вторичного источника или страница не открылась; `[устарело]` — сведения заменены более новыми. Состояние знаний — октябрь 2026.

## 2. Основы game UX

**Рамка Hodent.** UX игры раскладывается на две опоры: usability (удобство) и engage-ability (вовлекаемость). Рамку использовали в разработке Fortnite. Компоненты — по [блогу Hodent](https://celiahodent.com/understanding-the-success-of-fortnite-ux/) (2019, обновлено 2020); подробно — в The Gamer's Brain, 2nd ed. ([books.md](books.md)).

| Опора | Компонент | Вопрос ревью |
| --- | --- | --- |
| Usability | Signs and feedback | Каждый сигнал понят так, как задумано? Каждое действие получает отклик? |
| | Clarity | Читается ли элемент с первого взгляда, без расшифровки? |
| | Form follows function | Подсказывает ли форма элемента, что с ним делать? |
| | Consistency | Одинаковое выглядит и работает одинаково на всех экранах? |
| | Minimum workload | Минимальна ли когнитивная нагрузка (память, внимание) и физическая (число кликов)? |
| | Error prevention and recovery | Нет ли ошибок «не по замыслу»? Можно ли легко исправить ошибку? |
| | Flexibility and accessibility | Переназначение ввода, субтитры, режимы для дальтоников; ничего только цветом |
| Engage-ability | Motivation | Ясны ли цели и награды? Есть ли компетентность, автономия, связанность? |
| | Emotion | Game feel, присутствие, новизна |
| | Game flow | Баланс вызова, темп, онбординг |

Usability Hodent называет близкой к эвристикам других индустрий, а engage-ability — «более размытым» понятием. Для ревью интерфейса берите usability-половину. Engage-ability разбирается в [foundations.md](foundations.md) и [design-review.md](design-review.md).

**Границы восприятия.** Отклик меньше 0.1 с ощущается мгновенным. До 1 с поток мысли не прерывается, но задержка заметна. После 10 с внимание уходит, нужен индикатор прогресса и возможность прервать. Это пороги Nielsen (1993) по Miller (1968) и Card et al. (1991). Для игры с прямым управлением 0.1 с — потолок, а не цель: ощущение управления описано в [foundations.md](foundations.md#14-game-feel-и-сок-swink-jonasson--purho-nijman).

**Где искать примеры и практику.**

- [Game UI Database](https://www.gameuidatabase.com/) (Edd Coates) — бесплатная база скриншотов и видео интерфейсов с фильтрами по типу экрана, цвету, управлению, паттернам и элементам HUD. По Creative Bloq, в версии 2.0 (2024) больше 55 тысяч скриншотов из 1 341 игры `[не проверено]`. Перед использованием скриншотов в коммерческой работе проверьте права.
- Game UX Summit — отраслевая конференция по game UX. Первую провела Epic Games в 2016 году, дальше хост менялся: Ubisoft Toronto (2017), EA (2018).
- Доклады: Hodent, «Developing a UX Mindset on Fortnite» (GDC 2019); Ignacio, Dead Space UI (GDC 2013); Sakamoto, Hearthstone UI (GDC 2015). Ссылки — в [разделе 9](#9-источники).
- Эвристики интерфейса (Nielsen 10, Pinelle) и cognitive walkthrough — в [design-review.md](design-review.md#33-nielsen-10-для-интерфейса).

## 3. HUD и типы интерфейса

**Первоисточник таксономии** — магистерская работа Fagerholt & Lorentzon (Chalmers, 2009, совместно с EA DICE) о шутерах от первого лица. Две оси: принадлежит ли элемент фикции игры и находится ли он в 3D-пространстве игры.

| Категория у Fagerholt & Lorentzon | Фикция | Пространство | Пример из работы |
| --- | --- | --- | --- |
| Non-diegetic (HUD) | нет | нет | Классические полоски и счётчики поверх экрана |
| Geometric | нет | да | Контуры союзников в Left 4 Dead, runner vision в Mirror's Edge |
| Meta-representations | да | нет | Телефон в GTA IV, показанный поверх экрана |
| Meta-perception | обычно нет | нет | Кровь на экране, звук сердцебиения, пульсирующая вибрация при низком здоровье |
| Diegetic | да | да | Dead Space, Far Cry 2 |
| Signifiers (подвид diegetic) | да | да | Дым от оружия, которое скоро сломается |

**Популярная четвёрка** diegetic / non-diegetic / spatial / meta пошла от статьи Marcus Andrews (Gamasutra, 2010). В ней «spatial» соответствует geometric, а «meta» объединяет обе meta-категории. Четвёрки хватает для разговора в команде. Для ревью полезнее исходная версия: она отделяет «где элемент» от «существует ли он в мире».

**Как выбрать тип.**

1. **Чем соревновательнее игра, тем важнее однозначность.** Гайдлайн «Know Your Game» у Fagerholt & Lorentzon: в играх мастерства non-diegetic и geometric элементы дают ясную информацию, которую трудно передать диегетикой. В повествовательных играх диегетика и сигнификаторы усиливают присутствие, и некоторая неоднозначность допустима.
2. **Производительность игрока важнее погружения.** Andrews: игроки WoW принимают настраиваемый non-diegetic HUD, когда он помогает играть. Полностью диегетический интерфейс шутера он считает почти непрактичным.
3. **Диегетика требует проверки.** В Dead Space голографическая карта не помогла ориентироваться, и команда добавила диегетический «locator» — путь, проецируемый на пол (Andrews 2010). Как пришли к диегетическому UI, рассказывает Ignacio (GDC 2013).
4. **Смешение допустимо.** Team Fortress 2 смешивает диегетику, non-diegetic и пространственные элементы. Выглядит пёстро, но игроки это принимают (Andrews 2010).
5. **Минимальный HUD — не отсутствие информации.** Информация переезжает в мир (Dead Space: здоровье на спине костюма) или в каналы meta-perception (звук, вибрация). Проверьте, что новая форма читается так же быстро, как прежняя полоска.
6. **Звук и вибрация — тоже интерфейс.** Fagerholt & Lorentzon прямо относят сердцебиение и вибрацию к meta-perception. Для доступности такие сигналы дублируются визуально (XAG 103, [design-review.md](design-review.md#62-xbox-accessibility-guidelines-xag-v32)).

## 4. Читаемость, иерархия, цвет, текст

**Иерархия и шум.** Riot определяет ясность как способность понять, что происходит, и ответить. Цели: геймплей передан ясно, иерархия сохранена, шум минимален. Внимание к элементу соразмерно его влиянию на игру: сильный эффект должен быть заметнее слабого. Косметика (скины) не должна быть менее ясной, чем базовый вариант («Clarity in League», 2021). Перенос на любой жанр:

- составьте список элементов экрана и расставьте ранги: что нужно для решения прямо сейчас, что — для плана, что — справка;
- первый ранг — крупнее, контрастнее, ближе к точке взгляда; третий — по запросу (тултип, отдельный экран);
- проверьте худший случай: максимум одновременных событий и эффектов.

**Иконография.** Иконка проверяется на людях, а не на команде. Пример Hodent: иконку ловушки в Fortnite принимали за патроны или деревья; после теста её заменили на капкан. Иконке нужны узнаваемый силуэт и единый стиль по всей игре (consistency). Новую иконку при первом показе можно подписать.

**Цвет и форма.**

- Около 1 из 12 мужчин имеет нарушение цветового зрения, чаще всего красно-зелёное (NEI).
- Не передавайте информацию только цветом: добавляйте форму, положение, штриховку, подписи прямо на объекте. Контраст по яркости важнее контраста по оттенку (Okabe & Ito 2002; Hodent 2019; GAG).
- Палитра Okabe & Ito различима при основных типах дальтонизма. Пресеты для дальтоников — дополнение, а не замена дублированию формой.
- Чем меньше цветов в коде, тем проще. UX-дизайнер Legends of Runeterra писал, что игра использует только два цвета подсветки (синий и золотой). Цвет труден для дальтоников и плохо читается на разных игровых полях, а попытка цветом показать владельца заклинаний ухудшила ясность.

**Размер текста** (XAG 101: высота от нижнего выносного элемента до верхнего, минимум при запуске игры):

| Платформа | Разрешение или плотность | Минимум |
| --- | --- | --- |
| Консоль | 1080p / 4K | 26 px / 52 px |
| ПК, VR | 1080p / 4K | 18 px / 36 px |
| Мобильные, стриминг | 100 / 200 / 400 DPI | 18 / 36 / 72 px |

Текст должен масштабироваться в настройках. Для абзацев длиннее двух строк XAG 101 даёт: не больше 80 символов в строке (40 для CJK), интерлиньяж от 1.5. Как мерить высоту шрифта по скриншоту, описано там же. Контраст — XAG 102 ([design-review.md](design-review.md#62-xbox-accessibility-guidelines-xag-v32)). Для iOS Apple даёт минимум 11 pt.

**Отклик.** Каждое действие получает отклик в пределах 0.1 с, даже если результат придёт позже: подсветка, звук, анимация намерения. Что именно сообщает отклик, проверяйте по шагам обратной связи Koster ([foundations.md](foundations.md#14-game-feel-и-сок-swink-jonasson--purho-nijman)). Сетевое подтверждение и откат описаны в [architecture-code.md](architecture-code.md) → П29.

## 5. Меню, потоки экранов, ввод, локализация

**Потоки, а не экраны.** Joseph Kim (2014) советует проектировать пути игрока, а не отдельные экраны. Для каждой кнопки задайте вопрос «что будет, если нажать X?». Так скрытые функции всплывают до разработки, а не после. Его рабочий формат — схема экранов со стрелками и заглушками; сначала итерируются потоки, потом схема поддерживается как сводка.

**Порядок работы над экраном.**

1. Список задач игрока на экране и их частота. Частые задачи — в один-два шага.
2. Карта потоков: вход, выходы, возврат, ошибки, «необычные пути» (Roblox Creator Docs советует учитывать и их).
3. Вайрфрейм без арта: структура, иерархия, состояния (пусто, загрузка, ошибка, переполнение).
4. Кликабельный прототип в Figma или аналогичном инструменте. Тест с 5 людьми на задачах ([playtesting-metrics.md](playtesting-metrics.md#5410-обучение-и-онбординг)).
5. Арт и анимации только после того, как поток прошёл тест.

**Состояния и навигация.**

- Каждому экрану нужны состояние по умолчанию, видимый фокус и предсказуемый «назад».
- Геймпад: навигация фокусом, а не виртуальным курсором. Paradox при переносе Crusader Kings III на консоли сразу отказалась от виртуальной мыши на стике. Вместо неё фокус переключается между открытыми панелями и картой, частые функции вынесены в радиальные меню, а подсказки кнопок меняются по контексту внизу экрана (Console Dev Diary #3, 2022).
- На консоли навигация последовательная, поэтому далёкие элементы нужно дублировать шорткатами (Roblox console guidelines).
- Клавиатура: все действия доступны без мыши; горячие клавиши показаны в тултипах.
- Тач: цели не меньше 44×44 pt (Apple) или 48×48 dp с зазором 8 dp (Android); перетаскивание дублируется нажатием ([design-review.md](design-review.md#64-быстрый-проход-доступности)).
- Пункты XAG 112 (навигация) и 113 (фокус) — в [design-review.md](design-review.md#62-xbox-accessibility-guidelines-xag-v32).

**Локализация.**

- Перевод с английского на европейские языки удлиняет короткие строки сильнее всего. Таблица IBM в статье W3C: до 10 символов — 200–300% длины оригинала, 11–20 — 180–200%, больше 70 — около 130%.
- Нелатинские письменности требуют больше высоты строки: тайский текст в примере W3C занимает около 150% высоты латиницы.
- RTL (арабский, иврит): раскладка зеркалится, отступы задаются как start/end, а не left/right. Стрелки «вперёд» смотрят влево (Android Developers). Что зеркалить, а что нет (медиа-иконки, числа, логотипы), Android отсылает к гайду Material Bidirectionality; его страница в этой сессии не открылась `[не проверено]`.
- Проверка: псевдолокализация (удлинённые строки с диакритикой) на всех экранах до перевода.

**Разрешения и safe areas.**

- Телевизор: весь важный текст и UI — в title-safe area, это внутренние 90% экрана у Xbox (1720×1000 при 1080p, отступы 96 px по бокам и 40 px сверху и снизу). Action-safe — 95%.
- Мобильные: safe area системы (вырезы, скругления, жестовые зоны); раскладка под разные соотношения сторон. MTG Arena при выходе на телефоны отдельно меняла UX/UI под маленький экран, тач и разные соотношения сторон (FAQ 2021).
- Якоря и масштаб: UI привязан к краям и safe area, а не к абсолютным пикселям; масштаб текста работает на всех разрешениях.

## 6. UI по жанрам

Пункты — отправные точки для ревью. Источник указан там, где он проверен. Общие правила разделов 3–5 действуют во всех жанрах.

### 6.1. Шутеры и экшен

- Соревновательный режим требует однозначной информации: non-diegetic и geometric элементы (Fagerholt & Lorentzon 2009, «Know Your Game»).
- Состояние персонажа можно передавать каналами meta-perception: кровь на экране, сердцебиение, вибрация. Важное дублируйте визуально (Fagerholt & Lorentzon 2009; XAG 103).
- Диегетический HUD (Dead Space) проверяйте на скорость чтения в бою; навигацию в Dead Space пришлось дополнить «locator» на полу (Andrews 2010; Ignacio 2013).
- Сила визуального эффекта соразмерна угрозе: от чего можно увернуться, то заметнее (Riot, «Clarity in League»).
- Пространственные маркеры союзников и целей (контуры L4D) — geometric элементы: в мире, но не в фикции.
- Обучающий текст не показывать во время боя (Hodent 2019).

### 6.2. RPG

- Плотность информации высокая: статы, предметы, квесты. Решение — ранжирование и раскрытие по запросу (раздел 4).
- Большой инвентарь требует сортировки, фильтров и поиска. Сравнение предмета с надетым показывайте прямо в подсказке `[не проверено]`: каноничного источника по инвентарям RPG не найдено, только разборы сообщества.
- Подсказка клавиши рядом с объектом снимает нагрузку на память: в Fortnite HUD показывает, какую клавишу нажать, чтобы обыскать предмет (Hodent 2019).
- Закрепление цели в HUD (рецепт, квест) экономит переходы в журнал: в Fortnite рецепты крафта можно закрепить в HUD (Hodent 2019).
- Субтитры диалогов: размер, подложка, имя говорящего ([design-review.md](design-review.md#6-доступность), XAG 104).

### 6.3. Стратегии, RTS, 4X

- Вложенные тултипы: понятие в тексте выделено цветом и раскрывается своим тултипом, который можно закрепить. Paradox ввела их в Crusader Kings III и взяла за основу в Europa Universalis V; плотные числа там показываются таблицей в тултипе (Tinto Talks #77, 2025).
- Самые частые приказы — в один клик или клавишу; горячие клавиши видны в тултипах.
- Превью последствий приказа (путь, урон, исход) сокращает пересчёты. Into the Breach показывает намерения врагов заранее ([mechanics-patterns.md](mechanics-patterns.md) → О5).
- На геймпаде — фокус и радиальные меню, а не виртуальная мышь (CK3 Console Dev Diary #3).
- Уведомления ранжируются: что требует решения сейчас, а что подождёт.
- Обратная сторона: игроки CK3 жаловались на перегруженный экран и всплывающие подсказки `[не проверено]`. Плотность нужно мерить тестом 5 секунд и временем поиска.

### 6.4. Платформеры и аркады

- Главный канал информации — сам персонаж и мир; HUD минимален. Время отклика и ощущение управления — [foundations.md](foundations.md#14-game-feel-и-сок-swink-jonasson--purho-nijman).
- Каждый элемент HUD должен отвечать на вопрос, нужен ли он для решения прямо сейчас. Если нет — показывать по событию (сбор, урон) и прятать.
- Прощение ошибок ввода (coyote time, буфер) — часть интерфейса управления: [mechanics-patterns.md](mechanics-patterns.md#11-управление-и-ощущение).
- Быстрый рестарт после ошибки снижает цену эксперимента ([mechanics-patterns.md](mechanics-patterns.md) → О6).

### 6.5. Гонки

- Гоночная линия может показывать не только маршрут, но и идеальную скорость и траекторию. Режимы: всегда, никогда, только при торможении; прозрачность настраивается (The Crew Motorfest, Ubisoft 2023).
- Белый текст HUD без подложки плохо читается на скорости. В The Crew Motorfest добавили сплошные контрастные подложки, отключаемые ради погружения.
- Каждый элемент HUD и уведомления отключаются по отдельности (там же).
- Цвет используется минимально, есть пресеты для частых типов дальтонизма (там же).

### 6.6. Спорт

Проверенного первоисточника по UI спортивных игр в этой сессии не найдено. Применяйте общие правила:

- телевизор как основной экран: title-safe area и минимумы текста для консоли (разделы 4 и 5);
- иерархия: управляемый игрок, мяч и счёт — первый ранг (Riot, «Clarity in League», как общий принцип);
- одинаковые обозначения в меню и в матче (Hodent: consistency).

### 6.7. Головоломки

- Превью результата до действия: ghost piece в Tetris показывает, куда упадёт фигура, и доступен всегда в играх по Tetris Guideline (TetrisWiki).
- Отмена хода и быстрый рестарт уровня снижают цену эксперимента (Hodent: error prevention and recovery; [mechanics-patterns.md](mechanics-patterns.md) → О6).
- Состояние доски должно читаться без анимаций: анимация поясняет переход, но конечное состояние понятно и без неё.
- Подсказки по запросу, а не навязанные: решение остаётся за игроком.

### 6.8. Карточные и настольные игры

- Интерфейс здесь почти вся игра. Sakamoto (GDC 2015, по пересказу MeinMMO): мира нет, поэтому UI составляет почти всю игру. В Hearthstone погружение в меню иногда ставили выше удобства: заменить карту в колоде можно было только за много кликов.
- Читаемость карты: стоимость, сила и ключевые слова с подсказками. Чем меньше надо объяснять, тем лучше: «anything you don't have to explain to your player is a godsend» (Dodds, GDC 2014). Бюджет сложности текста — [mechanics-patterns.md](mechanics-patterns.md) → О2, О3.
- Превью исхода до подтверждения: Oracle's Eye в Legends of Runeterra показывает, как разрешится цепочка заклинаний и куда придёт урон. При случайных эффектах его выключают (Riot Support; UX-дизайнер LoR).
- Автоматизация приоритета: MTG Arena сама даёт приоритет в типовых ситуациях (smart priority), для редких линий есть стопы и full control (Wizards, 2025). На телефоне full control включается долгим нажатием на аватар (FAQ 2021).
- Отмена до конца хода: Marvel Snap разрешает вернуться к расстановке, пока соперник не закончил ход (патч 12.03.2024).
- История действий: Hearthstone показывает последние действия слева от поля (hearthstone.wiki.gg). Таймер хода с видимым индикатором — [mechanics-patterns.md](mechanics-patterns.md#3-мини-каталог-паттернов).
- Анимации не блокируют логику и ввод: Riot отдельно правила скорость анимаций и блокировку ввода в LoR (Inven Global, 2020). Архитектура — [architecture-code.md](architecture-code.md) → П23.
- Мобильная раскладка — отдельный дизайн. Arena на телефоне переделывала UX/UI под тач, атака и блок там делаются тапами (FAQ 2021). Перетаскивание дублируется нажатием ([design-review.md](design-review.md#64-быстрый-проход-доступности)).

### 6.9. Мобильные и казуальные

- Хват различается. Hoober (2013, 1 333 наблюдения, из них 780 с касанием экрана): одной рукой 49%, в одной руке с касанием другой («cradled») 36%, двумя руками 15%. В 2017 году он обновил выводы, поэтому проверяйте свою аудиторию.
- Частые действия — в зоне досягаемости большого пальца; редкие и опасные — дальше от неё `[не проверено]`: это вывод из данных Hoober, а не его формулировка.
- Цели касания 44×44 pt или 48×48 dp, зазор 8 dp (Apple; Android).
- Safe area и вырезы экрана; текст не меньше минимумов XAG 101 для мобильных.
- Сессии короткие: состояние сохраняется при сворачивании, возврат в то же место. Kim (2014) советует считать пути, а не экраны.

### 6.10. MMO

- Настраиваемый non-diegetic HUD: игроки WoW принимают его, когда он помогает играть (Andrews 2010).
- Плотность информации максимальная: ранжирование, отключаемые панели, сохранение раскладки.
- Чат и социальные уведомления не перекрывают информацию первого ранга.
- Каждый элемент HUD отключается и перемещается (общее правило гибкости у Hodent; пример The Crew Motorfest).

### 6.11. VR

- Привычный HUD поверх экрана в VR работает плохо, поэтому VR тянется к диегетике и пространственному UI (таксономия Fagerholt & Lorentzon, раздел 3).
- Дистанция по Meta: для взаимодействия лучом — от 0.8 до 3 м, не ближе 0.8 м; для касания — панель в 42–46 см от игрока.
- Если панель приближается или удаляется, сохраняйте её угловой размер, а не физический: иначе текст мельчает и в него трудно попасть (Meta).
- Частые элементы касания — в нижней половине панели: поднятые руки быстро устают. Интерактивные элементы не ставьте так низко, чтобы игрок всё время смотрел вниз (Meta).
- Head-locked UI (закреплённый в поле зрения) оставляйте только для критичного (Meta описывает его как способ держать важное видимым).
- Следование рекомендациям не гарантирует комфорт: нужен итеративный тест на людях (Meta, Comfort).

## 7. Как мерить UI

Интерфейс меряется на людях: бот не мисскликает и не ищет кнопку. Методы плейтеста, размер выборки и опросники — в [playtesting-metrics.md](playtesting-metrics.md).

| Метод | Что меряет | Когда | Источник |
| --- | --- | --- | --- |
| Задачи с секундомером | Успех задачи, время, ошибки | Каждый новый экран и поток | [playtesting-metrics.md](playtesting-metrics.md#5410-обучение-и-онбординг) |
| Think-aloud и cognitive walkthrough | Где игрок ошибается и почему | До и после правки | [design-review.md](design-review.md#33-nielsen-10-для-интерфейса) |
| Тест 5 секунд | Что игрок запомнил с экрана: первое впечатление и иерархия | Плотные экраны: HUD, магазин, стол | Термин — Christine Perfetti, середина 2000-х (Smashing Magazine, 2023). Меряет восприятие, а не юзабилити |
| Тепловые карты кликов и касаний | Куда нажимают, мисклики | Тач и меню | Maze: misclick rate — доля кликов вне активных зон |
| SUS | Субъективная юзабилити, 10 пунктов | Меню, магазин, редакторы | [playtesting-metrics.md](playtesting-metrics.md#3-опросники) |
| A/B в live | Конверсия потока, отказ на шаге | Когда трафика хватает | [playtesting-metrics.md](playtesting-metrics.md#4-телеметрия-и-kpi) |
| Замер по скриншоту | Высота шрифта, контраст, safe area | Каждая платформа | XAG 101, 102; Xbox: Screen areas |

**Какие поля писать.** Схема стенда та же, что в [pipeline.md](pipeline.md#этап-7-измерительный-стенд): JSONL, одна строка на единицу анализа. Для интерфейса удобны два уровня.

Строка на действие (решение игрока):

```json
{"session": "p07-s1", "player": "p07", "build": "ui-v2", "screen": "shop", "input": "touch",
 "action": "buy", "time_to_action_ms": 4200, "misclick": false, "undo": false, "invalid": false,
 "wrong_target": false, "tooltip_opens": 1}
```

Строка на игрока в сессии (сводка):

```json
{"session": "p07-s1", "player": "p07", "build": "ui-v2", "input": "touch", "misclicks": 3, "undo_count": 2,
 "invalid_attempts": 1, "timeouts": 0, "tooltip_opens": 9, "time_to_first_action_ms": 7400,
 "task_success": true, "sus": 72.5}
```

| Поле | Тип | Смысл |
| --- | --- | --- |
| `screen`, `input`, `build`, `action` | строка | Разрезы: экран, способ ввода (`mouse`, `pad`, `touch`), версия интерфейса |
| `time_to_action_ms` | число | Время от момента, когда действие стало доступно, до ввода |
| `misclick` | bool | Нажатие вне активной зоны или по соседнему элементу, отменённое в течение пары секунд; правило фиксируется в стенде |
| `undo` | bool | Действие отменено |
| `invalid` | bool | Попытка недопустимого действия: игра отказала |
| `wrong_target` | bool | Выбрана не та цель, игрок потом об этом сказал или отменил |
| `tooltip_opens` | число | Сколько раз открыты подсказки: много — понятие неясно |
| `timeouts` | число | Ходы или экраны, на которых истёк таймер |
| `task_success` | bool | Задача плейтеста выполнена |
| `sus` | число | Балл SUS после сессии |

Как считать:

```bash
python3 scripts/design_metrics.py runs/ui_actions_before.jsonl \
  --rate misclick --rate undo --rate invalid --num time_to_action_ms \
  --by screen --by input --meta build=ui-v1 --out metrics/ui_before.json
python3 scripts/metrics_compare.py metrics/ui_before.json metrics/ui_after.json --targets design/targets.json
```

Коридоры в `design/targets.json` задаёт команда, например `"rate:misclick@input=touch": {"better": "lower"}` и `"num:time_to_action_ms@screen=shop": {"better": "lower", "stat": "median"}`. Готовых отраслевых норм для этих метрик в играх не найдено.

**Оговорки.**

- Строки на действие одного человека зависимы. При 5–10 людях интервалы по действиям получаются слишком узкими. Сравнивайте сводки на игрока или читайте числа как ориентир, а не доказательство.
- `time_to_action_ms` смешивает поиск кнопки и обдумывание хода. Отделяйте экраны интерфейса (меню, магазин) от экранов решений (ход в партии) разрезом `--by screen`.
- Мисклик определяется до замера и не меняется между версиями: стенд — контракт ([pipeline.md](pipeline.md#этап-7-измерительный-стенд)).

## 10. Расхождения и пробелы

**Расхождения.**

1. **Четыре или шесть типов UI.** У Fagerholt & Lorentzon (2009) шесть групп на осях «фикция × пространство», и вместо «spatial» стоит «geometric». Четвёрка diegetic / non-diegetic / spatial / meta — упрощение Andrews (2010), которое потом пересказывают как классификацию Fagerholt & Lorentzon.
2. **Диегетика и погружение.** Fagerholt & Lorentzon видят пользу диегетики в повествовательных играх. Andrews считает её пользу во многом субъективной: игроки ценят производительность. Противоречия нет, если учитывать соревновательность игры.
3. **Погружение или удобство.** В Hearthstone погружение в меню иногда ставили выше удобства (пересказ доклада 2015 года). Hodent и Nielsen ставят на первое место минимальную нагрузку. Разумный компромисс: погружение в рамке, удобство в частых операциях.
4. **Год доклада Hodent.** Страница GDC Vault указывает GDC 2019; в поиске встречается и GDC Showcase 2021, вероятно, как повторный показ.
5. **Размер текста.** XAG 101 даёт 26 px для консоли при 1080p; на сторонних сайтах встречается 28 px. Опирайтесь на страницу XAG.
6. **Safe area.** У Xbox 90% — title-safe, 95% — action-safe. В телевещании встречаются другие схемы (80% / 90%). Берите документ своей платформы.
7. **Таблица IBM у W3C:** строка 51–70 символов (151–170%) больше строки 31–50 (140–160%). Похоже на опечатку источника.

**Пробелы.**

- Нет официального описания auto-pass в MTG Arena; есть только smart priority и мобильный FAQ.
- Нет проверенных первоисточников по UI спортивных игр и по инвентарям RPG.
- Нет опубликованного игрового кейса с замерами мисскликов или времени до действия. Коридоры для метрик раздела 7 команда задаёт сама.
